# Agentic pipeline architecture review and upgrade design

## Decision

The product flow is a bounded, session-local iterative design loop. The Planner owns intent and review; Layout IR owns geometry; Qwen-Image-2.1 owns pixels; the verifier stack owns safety and measurements. No model may silently take another model's responsibility.

## Current implementation audit

The current code correctly wires Planner -> constraint merge -> LayoutBackend -> wireframe and Finalize -> mandatory handoff -> Qwen-Image-2.1 -> verifier -> persisted output. Conversation history and prior critique are passed to the Planner, and optimistic revisions protect writes.

The following requested behavior is not yet implemented and is a release blocker:

1. Every message currently runs one Planner+Sketch turn, but there is no explicit four-turn budget.
2. There is no inactivity/debounce scheduler that triggers a Planner self-review while the sketch is visible.
3. There is no distinction between user-driven turns and autonomous self-review turns.
4. Finalize eligibility is based on the existence of a layout reference, not on completion of the bounded refinement policy.
5. Planner context is limited incidentally by the backend's last six messages, not by a session policy with an explicit summary and original-intent anchor.
6. Critique and enhancement paths need to be modeled as post-finalization revision cycles, not as a second hidden design loop.
7. The current Qwen backend supports image handoff; its text-to-image capability should be an explicit opt-in only for sessions without a sketch, never an accidental fallback.

## Final state machine

```text
CONVERSING
  -> SKETCHING
  -> REFINING (user or planner self-review, max 4 turns)
  -> FINALIZING
  -> FINALIZED
  -> POST_REVIEW (optional user request)
  -> REFINING (new bounded revision cycle)
```

A `turn` is one Planner decision plus one Layout projection. A user message consumes one turn. A self-review consumes one turn. The default policy is `max_refinement_turns=4`, configurable per session but capped by a server maximum.

### User messages while sketch is visible

- Cancel or supersede a pending self-review timer.
- Add the message to this session's history.
- Run Planner with original intent, active constraints, recent bounded history, and the current wireframe reference.
- Merge the delta and regenerate Layout IR.
- Increment the refinement counter.

### No user response

The server does not infer silence from an HTTP request. A session coordinator schedules a self-review after an explicit inactivity window. The self-review prompt is deterministic and must include the original intent, active constraints, current layout summary, and unresolved verifier/review findings. It produces a normal Planner delta and consumes one turn.

After four turns, the coordinator stops self-review scheduling and offers/starts Qwen finalization according to the product policy. This prevents autonomous drift.

## Context policy

The Planner receives only session-local context:

- immutable `original_intent`;
- current validated constraints;
- current Layout IR summary and revision;
- last `N` conversation turns (recommended N=6 messages, not six user/planner pairs);
- a bounded summary of older turns;
- latest Planner review findings;
- turn counters and reason (`user_message` or `self_review`).

The session summary is generated by the Planner but validated and length-limited by the application. It is not global memory. When a new user instruction conflicts with the original intent, the Planner must emit an explicit replacement or amendment field; silent replacement is prohibited.

## Finalization policy

Finalize only after:

- a valid Layout IR and wireframe exist;
- the refinement budget is exhausted or the user explicitly requests finalization;
- the handoff is a pixel image reference;
- the effective prompt is frozen;
- Qwen-Image-2.1 is available.

Qwen receives `prompt` plus `image=handoff_image`. The image-conditioned path is the default. Text-to-image is allowed only for an explicit `direct_generation` request with no design session handoff; it must be separately logged and never selected after a failed image handoff.

## Post-finalization upgrades

A user request after Finalized starts a new revision cycle with:

- the finalized image as the current visual artifact;
- the original session intent;
- current constraints;
- verifier scores;
- a new counter capped at four.

The system must not mutate the prior final artifact. Each revision creates a new provenance record, enabling research comparison between candidates.

## Training architecture review

The active training path now matches Qwen's official contract:

```text
condition image + target image + instruction
  -> train_dreambooth_lora_qwenimage21_img2img.py
  -> Qwen-Image-2.1 LoRA + manifest
  -> startup adapter validation
  -> Qwen image-conditioned inference
```

The removed Z-Image flow-matching DPO path was a hard incompatibility, not merely an implementation preference. Its velocity target, transformer call shape, and preference loss assumptions were architecture-specific.

Training breakage points requiring explicit gates:

- condition/target filename pairing;
- no target-as-condition identity pairs;
- image dimensions and aspect-ratio policy;
- caption/instruction presence;
- train/validation split by design/session, not adjacent files;
- adapter manifest and base-model hash;
- exact Diffusers revision;
- target-GPU peak memory and checkpoint reload.

## Research evaluation plan

Report separate distributions for:

- Planner constraint accuracy;
- four-turn improvement curve;
- user-vs-self-review turn contribution;
- layout validity and locked-region preservation;
- handoff consistency;
- OCR readability;
- semantic prompt alignment;
- aesthetic preference;
- safety pass rate;
- finalization latency and peak VRAM;
- post-finalization revision improvement;
- base Qwen vs Qwen+LoRA under identical handoffs, prompts, seeds, and verifier versions.

Do not report a single aggregate score without publishing normalization, weights, confidence intervals, and failure handling.

## Implementation sequence

1. Add explicit refinement policy fields and state transitions.
2. Add a session coordinator with cancellable inactivity self-review scheduling.
3. Add Planner self-review mode and bounded context summarization.
4. Make finalize gating consume the policy state, not only `layout_ref`.
5. Add post-finalization revision-cycle semantics.
6. Add direct text-to-image as a separately named, explicitly requested mode.
7. Add lifecycle and research telemetry.
8. Validate on target hardware and revise budgets only from measurements.

## Implementation status

The first policy slice is implemented:

- `DesignState.refinement` stores a per-session, per-cycle four-turn budget;
- user and autonomous turns are distinguished;
- a finalized session starts a new bounded revision cycle when the user sends
  a new message;
- exhausted cycles fail explicitly rather than silently losing context;
- `planner_self_review()` executes one autonomous Planner/Layout turn without
  fabricating a user conversation turn;
- `POST /session/{session_id}/self-review` exposes the operation for the
  upcoming inactivity coordinator.

The inactivity coordinator is now implemented in
`orchestrator/session_coordinator.py`. It debounces per-session user activity,
cancels pending work on a new message, dispatches self-review after
`KRIVEX_SELF_REVIEW_IDLE_SECONDS` (default 30 seconds), and reschedules only
while the persisted four-turn budget remains. Shutdown cancels and awaits all
pending tasks.

The remaining production work is observability, multi-process deployment
coordination, and target-hardware validation. The current coordinator is
process-local by design; a horizontally scaled deployment must move its timer
ownership to a durable job system or enforce session affinity.

Refinement events are persisted in `DesignState.refinement_events`. The ledger
records turn start/completion, budget exhaustion, and self-review scheduling
with cycle, source, timestamp, and detail. It is bounded by the session's
retention policy; production telemetry can export these events asynchronously
with session identifiers pseudonymized.
