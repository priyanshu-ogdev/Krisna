# inference/runtime/ — CLI Session Harness

A CLI harness for running a real agentic session end-to-end against
checkpoints in `models/` or with `MockBackend` — for manually testing trained models
and validating multi-turn agentic orchestration without starting the web UI.

`run_agentic_session.py` delegates directly to the canonical package CLI
entry point `krisna-session` (`krisna_inference.cli:main`).

## Usage

```bash
# Safe default — MockBackend, no GPU, no models/ checkpoints needed.
python inference/runtime/run_agentic_session.py --finalize --critique
# Or via canonical console script:
krisna-session --finalize --critique

# Real backends — GPU required, reads models/ checkpoints via the same
# KRISNA_* env vars scripts/inference/run_service.sh uses:
python inference/runtime/run_agentic_session.py --real --finalize

# Low-VRAM / CPU-offload mode (PRD §3, §7.3):
python inference/runtime/run_agentic_session.py --real --low-vram --finalize

# Multi-turn scripted session, quality polish tier, with critique:
python inference/runtime/run_agentic_session.py --real \
    --message "a fintech dashboard" \
    --message "make the primary color teal and lock top navigation" \
    --finalize --finalize-tier polish_quality --critique
```

## Agentic Capabilities Verified (PRD §5.1–§5.3)

1. **Multi-Turn Context & History**:
   - Each `--message` advances the session turn through `flows.conversational_turn()`.
   - The CLI retains and forwards cumulative `conversation_history` into the Planner backend,
     ensuring subsequent turns preserve prior conversational context.
2. **Dynamic Constraint Merging**:
   - Structured JSON deltas generated by the Planner (`constraint_updates`, `locked_regions`,
     `color_palette`, `device_target`) are parsed and merged into `DesignState.constraints`.
3. **Conditioned Generation & Prompt Synthesis**:
   - Sketch generation tokens (`vq_tokens`) are grounded in the active intent and constraints.
   - When Finalize is invoked, the orchestrator synthesizes a rich, coherent rendering prompt
     from active constraints if no explicit prompt override is provided.
4. **Closed Critic Feedback Loop**:
   - When `--critique` is executed, structured critique output (`dimensions`, `suggested_edits`)
     is stored in `DesignState.critique` and automatically surfaced into subsequent Planner turns.
5. **Orchestration & Swap State Machine (PRD §7.4)**:
   - Verifies baseline unloading prior to Polish/Critic admission, VRAM/RAM ledger validation,
     and safe recovery rollback on OOM or errors.
